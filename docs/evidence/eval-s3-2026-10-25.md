## What this does and does not show

- **The prompt did not fail these questions.** Where the model was called with the right snippets (TC-01, 03, 06, 12, 20) it answered correctly with valid citations, and TC-20 kept grounding against an instruction to ignore the sources.
- **Retrieval is the main problem.** In 8 of 20 cases the right snippet never reached the model. This is the retrieval-threshold issue tracked in #88 (`MATCH_THRESHOLD` 0.5 drops narrow questions); the same issue means the scored factual rate says little about the prompt.
- **Scorer gap found by this run.** The canned reply "I couldn't find any spec information relevant to that question" is a correct refusal, but the scorer's refusal phrases do not include it, so TC-09, 10, 16 and 19 failed the abstention check although nothing was invented. The rule that an abstention must cite nothing also failed TC-08, 17 and 18, where the model said the spec was not given and named the snippet it did have.
- **No re-scoring is claimed here.** Changing the scorer or the rubric after seeing these results is a separate, labelled analysis on this same answers file (no new model calls), not a replacement for the numbers above.
- **No prompt change is justified by these results.** Most failures happen before the prompt runs, so a prompt v2 would not address them. The prompt stays at `v1`.
- **Limits:** one run, one sample of 20 questions over two gadgets, the dev database as it was at 07:42, and the answer cap settings from #103. Model output varies between runs.
