## Decision: no prompt revision after this run

The brief allowed at most one justified revision. I did not make one:

- Most of the score drop (TC-17, TC-19, TC-24, TC-09 under s4) comes from the model saying "on file", which `v2` itself asked for ("say its spec isn't on file"). The declines are correct when read. Rewording the prompt so that refusals hit the scorers' phrase lists would mean tuning the prompt to the scorer, which the handover forbids. Adding "on file" to a scorer after seeing these answers would be another post-hoc profile like s4/s5. Either is the owner's call, not a fix to make inside this run.
- TC-07 has failed in every run but one, so a single run cannot attribute it to `v2`.
- TC-08 (s5) is the stray dev chunk, not the prompt.
- TC-18 (still giving the base 6.1-inch) and TC-12 (over-hedging the PH model) suggest the variant sentence is not yet right. One more revision and one more run would not settle that, and it would start chasing scores.

**Recommendation to the owner:** do not release `v2` on these numbers. Keep `gk-v2`, which fixes GK-06 and touches nothing else. Options for the grounded prompt: (a) keep `v1` in production and record TC-24 as still open; (b) write a `v3` that keeps the "give no other model's value" part, but declines in the same terms as the existing ACCURACY rule ("say so plainly": the snippets don't state that variant's spec) instead of "on file". That is a product-wording decision, to be scored on its own run; (c) treat "on file" as an evaluator gap and add it in a separately labelled profile. Option (c) would not address TC-18.
