## Labelled rescoring (`--rules s4`, #66)

Three rules, chosen after reading the 25 and 26 Oct answers, applied only when `--rules s4` is given (the default stays `s3`): (1) the app's canned "couldn't find any spec information" reply counts as a refusal; (2) an abstention may cite a snippet it describes, but still fails if it states a spec value the question did not contain or cites a snippet outside the pack; (3) a forbidden fact counts only when a sentence asserts it, not when a refusal repeats it (a per-sentence negation heuristic).

## What the rescoring does and does not show

- **The rules were written after seeing the results**, so the `s4` numbers are not an independent measurement. The `s3` numbers stay the reference.
- **The 25 Oct credit is a safe outcome, not a model decision.** On that run the four canned replies (TC-09, 10, 16, 19) came from empty retrieval, so the model was never called. They now count as refusals, which is true of the outcome the user sees, but it does not show the model would have refused.
- **Remaining `s4` failures are scorer limits, left as they are** because they were not among the three rules. Examples from the 26 Oct scoped run: TC-08's refusal begins "None of the supplied snippets state…", which the refusal phrases do not recognise; TC-09, TC-18 and TC-19 list values the snippets contain while declining, and the spec-value check cannot tell that from asserting the asked-about value.
- **The negation rule is a heuristic.** It judges each sentence on its own, so a sentence that both asserts and negates would be read as a negation.
- **No prompt change.** The one real answer gap (TC-07) is a comparison-answer behavior, not something this run justifies tuning against; any change belongs in a new version scored on its own.
